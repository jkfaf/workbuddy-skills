# 游戏 UR 报告写作（game-ur-report）

把游戏用户研究的行业方法论装进报告写作流程。本技能解决三件事：**术语专业化**（口述需求 → 行业语言）、**结构行业化**（符合游戏公司 UR 团队的报告范式）、**定性技术落地**（记忆点/峰终定律等技术在报告中如何用）。

## 一、术语转换表（口述 → 行业语言）

用户的口述描述必须先转译成游戏 UR 术语再入报告：

| 口述说法 | 行业术语 | 报告中的正式表述 |
|---|---|---|
| 玩家不玩了 | 流失（churn） | 流失用户定义：连续 N 日无登录行为 |
| 玩家回来了 | 回流（win-back / return） | 回流用户定义：流失 N 日后重新登录 |
| 什么东西吸引回来的 | 回流拉动点（pull factor）/ 召回动机 | 回流触发因素与拉动点归因 |
| 推广/宣传 | 宣发（marketing / promotion） | 版本宣发：买量投放（UA）、品牌向内容、官方社媒触点 |
| 推送到玩家 | 触达（reach） | 触点曝光：推送（push）、信息流广告、社媒内容、KOL/达人 |
| 看了几秒就关掉 | 素材前 3 秒钩子效力不足 | 素材注意层衰减：首帧钩子（hook）未建立，跳出发生在 3 秒内 |
| 玩家不爱点 | 点击率（CTR）低 / 兴趣层转化不足 | 触达→注意→兴趣的漏斗中断点定位 |
| 3.0/3.1 版本 | 版本节点（version milestone） | 版本宣发周期与素材对应的版本节点 |
| 日美的区别 | 分市场差异（market-level difference） | 日本 / 北美双市场玩家行为与文化差异分析 |
| 下一轮访谈挖什么 | 追加研究议程（follow-up research agenda） | 假设清单（H1-Hn）驱动的下一轮定性研究设计 |
| 玩家特点 | 玩家画像（persona / profiling） | 分群维度：游戏史、付费档位、生命周期阶段、动机类型 |
| 玩家想看的内容 | 内容偏好（content preference） | 供需错配：宣发供给内容 vs 玩家需求拉动点 |

## 二、报告结构范式（腾讯 i-MUR 全生命周期法）

游戏公司 UR 团队的标准研究链路，报告章节按此展开：

```
1. 数据全貌（Data Overview）   —— DAU/MAU 漏斗、回流率基线、分市场盘子
2. 活跃 vs 流失对比            —— 画像差异、行为差异、显著性检验
3. 流失原因定位（归因拆解）    —— 内容耗尽型 / 成长受阻型 / 注意力转移型 / 技术受挫型
4. 回流分析                    —— 回流触发因素、拉动点量级×决定性排序、回流后留存
5. 宣发有效性诊断              —— 触达→注意→兴趣→行动四层漏斗，逐层衰减定位
6. 改进建议                    —— 供需错配表、素材策略、触点策略、版本节奏
7. 下一轮研究议程              —— 假设清单而非问题清单
```

结构纪律：**按漏斗/链路组织，不按人群对比组织**。人群对比（回流 vs 未回流）是每一层的分析透镜，不是章节结构。

## 三、定性技术（GDC 2025 CE / 腾讯 i-MUR）

- **记忆点（memory ball）**：玩家访谈回忆的不是完整体验，是离散记忆点。访谈产出按"记忆点→情感效价→可激活性"整理，而不是流水账。回流玩家的记忆点清单 = 召回素材的最高价值素材库。
- **峰终定律（peak-end rule）**：玩家对版本的总体评价由峰值体验+结束体验决定。流失原因分析需区分"过程不满"与"终局不满"（版本末期的枯竭感是最常见的终局流失诱因）。
- **体验自我 vs 记忆自我**：问卷测的是当下态度（体验自我），访谈测的是回忆重构（记忆自我）。两源冲突时不是数据错误，是两类自我在打架——报告要显性呈现这种冲突。
- **版本错位声明**：定性（针对版本 N）与定量（针对版本 N+1）的版本错位必须在研究设计章节显性声明，用四类证据标签（验证型/修正型/解释型/单源型）管理两源结论的可信度。

## 四、宣发向报告专项

- 漏斗四层定义：**触达 Reach**（有没有看到）→ **注意 Attention**（有没有停留，前 3 秒）→ **兴趣 Interest**（有没有点击/看完）→ **行动 Return**（有没有回登录）。
- 未回流三型归因：**触达缺失型**（没收到/收到了没印象）、**兴趣衰减型**（看到但几秒跳出——诊断金矿，说明内容供给有问题而非触达有问题）、**需求终结型**（对游戏整体失去兴趣，宣发无法解决）。三型比例决定宣发策略的发力重心。
- 供需错配表：当前宣发供给的内容主题 × 玩家实际拉动点，交叉标注"供给过剩/供需匹配/供给缺口"。
- 素材评估维度：钩子强度（前 3 秒）、信息密度、熟悉度唤醒（老玩家记忆点调用）、召回理由清晰度（为什么现在回来）。
- 分市场基准（Mistplay 2025，引用需核对）：日本玩家专注 1-3 款游戏、53% 经应用商店发现新游戏、偏好叙事驱动；美国玩家多游戏轮换（4+ 款）、77% 经 Facebook 发现、对登录奖励类钩子响应度高（60%）。

## 六、报告写作行业标准（Steve Bromley / Koji）

### 6.1 一页摘要的"电梯测试"
摘要是写给只读这一页的人（约 60% 干系人只读摘要）：**研究了什么为什么（1-2 句）→ 发现了什么（3-5 条具体洞察）→ 建议做什么（1-3 条可执行动作）**。自检标准："如果有人在电梯里问我这次研究结论，我照摘要能不能答上来。"

### 6.2 发现按主题分组，不按功能分组
按洞察类别（insight categories）组织发现，而非按游戏功能罗列。同一主题下的问题聚在一起讲，方便对应团队认领。禁止"设置页问题、商店页问题"式清单。

### 6.3 发现陈述四件套（Koji 格式）
每条发现 = **具体可行动的标题 + 证据（2-3 条玩家原话）+ 频次（"11/14 名受访者在 X 步骤放弃"）+ 含义（对决策意味着什么）**。
- 好标题："玩家在 API Key 步骤放弃设置，因为期望它从 OAuth 自动填充"
- 坏标题："玩家对设置流程有意见"——不可行动、无信息量。
- "玩家感受复杂"这类模糊表述禁止出现，必须写成"N 名玩家在 X 环节因 Y 原因做了 Z"。

### 6.4 双读者写作
报告有两类读者：当场听汇报的人，和 6 个月后转发阅读、研究者不在场的人。报告必须自带全部上下文（版本号、研究问题、任务、样本），让 6 个月后的读者无需追问即可理解。分层写作：设计/美术→需要 friction 点+玩家心智模型+原话；程序→需要 failure mode + 频次；高管/制作人→结论先行+影响面+附录备查。

### 6.5 建议的风险控制（Bromley 警告）
研究者给"解决方案"有风险（缺少可行性/成本/技术判断），行业做法是给 **challenge（"我们如何确保玩家知道这个谜题是推进必需的？"）** 而非直接方案，或在建议旁标注"需与制作/美术/程序评估可行性"。触达型报告（宣发向）例外：营销策略本就是 UR 可负责域，建议可落地但须绑定数据触发条件。

### 6.6 禁用含糊词（游戏行业反 weasel words）
以下词不给出具体所指则禁用：**"好玩"**（必须说明什么机制产生什么感受）、**"有吸引力/engaging"**（说什么留住注意力、为什么）、**"沉浸感"**（说什么锚定了玩家）、**"平衡"**（给什么比例什么目标）、**"玩家会喜欢"**（哪类玩家、什么需求）。具体性标准：不写"玩家会困惑"，写"3/8 受访者在 2:15 处错过跳过教程按钮"。

## 七、玩家旅程图与画像体系（gstack-game）

### 7.1 七类玩家画像（做分群画像/模拟走查时选用）
Casual Newcomer（首次 session，3 分钟耐心，测 FTUE/D1）/ **Interested Returner**（Day 2-3 回访，找深度，测 session 2 钩子/D7）/ Dedicated Player（Day 7，懂系统，测中期经济与进度）/ Hardcore Optimizer（Day 30+，找 exploit 与平衡问题）/ Content Creator（测直播性与传播性）/ **Returning Player**（Day 90 流失后回坑，查更新，测**回流 UX**——本技能核心人群）/ Custom。同一内容对不同画像可打 9/10 与 3/10 的分化分——报告结论必须绑定画像。

### 7.2 玩家旅程图（Player Journey Map）输出格式
```
时间    行为           情绪         标记    备注
0:00    打开推送       好奇                 干净的开屏
0:05    看到素材       无感         !!      文案墙，4 行
0:45    首次失败       挫败         !!      无提示无恢复路径
2:00    内容墙         无聊         XX      流失风险
```
标记体系：**OK**=符合预期 / **!!**=摩擦警告 / **XX**=严重·流失风险 / **??**=设计盲区。附情绪弧线（Emotion Arc）：好奇→投入→挫败→自豪→无聊，标出 !! 下探与 XX 坠落位置。回流研究可把此格式移植到"回流路径走查"（看到推送→点击→回登录→首日体验→再留存）。

### 7.3 关键时间检查点（回流/召回场景移植版）
0-10s 首印象（知道这是什么游戏吗）/ 10-30s 首交互（知道该干什么吗）/ 30s-2min 首个 aha 时刻（体验到核心循环了吗）/ 2-5min 首次失败+恢复 / 5-10min 首个有意义选择 / 首次付费提示（付费前理解价值吗）/ **第二次 session 开场（重入顺畅吗，还记得该干什么吗）** / **Day 90 回流者开场（3 分钟内能感知"有什么新东西值得我留下"吗）**。

## 八、测试协议与定性纪律（gstack-game playtest + 网易雷火）

### 8.1 可测假设格式
每个研究/访谈轮次须有可测假设："我们相信【具体判断】，本轮研究将通过观察【具体指标/信号】证实或证伪它，阈值是【X】。"模糊假设（"好玩吗？"）必须先锐化再开题。下一轮访谈以 H1-Hn 假设清单驱动，禁止罗列问题清单。

### 8.2 三角验证（triangulation）
每条核心发现须有 **≥2 类证据源**（观察/行为数据/访谈/问卷），单源发现必须标注"单源型"并降级处理。回流研究的三角：回流者自述拉动点（访谈）× 触点曝光-回登录归因数据（问卷/后台）× 回流后行为（留存）。

### 8.3 severity × frequency 优先级矩阵
发现优先级 = 严重度（mild/moderate/severe，流失相关=severe）× 频次（N/总数）。2 人提的最高严重度问题 > 8 人提的轻度问题，报告排序按此矩阵，不按提及次数排。

### 8.4 大样本定性调研（网易雷火 100 例法）
当电话/深访样本放大到 N=100 量级：分层随机抽样（等级/时长/付费/职业）→ 问题先易后难热身 → 开放式而非二选一 → 采访中依回答追问调整框架 → 报告三部分（结论/概览/正文+玩家画像）。小样本（15 例）的教训：只有 1-4 次提及的问题无法定优先级——这正是要问卷定量补充的原因。

## 九、写作纪律（与 ur-report-rigor 联动）

1. 逻辑树先行：先画研究问题树（RQ → 子问题 → 证据源），再动笔。
2. 证据账本：每个发现标注问卷题号 / 访谈编号，四类证据标签。
3. 发现陈述固定格式：**【分群】在【漏斗层/维度】上，【量化事实】，说明【解读】，So What【业务动作】**。
4. 摘要最后写，只放已过反例检验的结论。
5. 假设清单：下一轮访谈以 H1-Hn 假设驱动，每条假设标注来源发现、验证方式、预期分支。

## 十、输出格式约定

- 报告交付为单文件 HTML（内联 CSS），或按用户要求转 Word。
- 待填数据用黄色虚线占位块（.ph-block），待拍板建议用紫色虚线块（.sug），正文框架直接写死。
- 玩家引语用 blockquote + 受访者编号，保留口吻但标注所属分群。
