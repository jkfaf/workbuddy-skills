# 用户研究报告 · 逻辑骨架 (ur-report-rigor)

## 概述

写任何用户研究/调研报告时套用本骨架，把"逻辑性"从玄学变成可执行的检查机制。核心思想来自 GitHub diandian1001/user-research-sop V4.0（证据账本 + Agent Loop）并实践验证于游戏宣发向回流研究报告（2026-08）。

**适用场景**：用户研究报告、调研报告、访谈/问卷混合研究、宣发/营销效果诊断报告。
**不适用**：纯数据看板、新闻稿、公众号文章。

## 七条硬规则（写报告全程遵守）

1. **逻辑树先行**：动笔前先画全文逻辑树：业务问题 → 研究问题(RQ) → 每章回答哪个RQ → 每章结论。逻辑树未经确认不写正文。
2. **证据账本兜底**：每个核心结论必须登记出处（问卷题号/交叉表/受访者编号）。写不出出处的句子删除或进附录。
3. **发现陈述固定格式**：结论一句话 → 数据支撑（n、占比、差值）→ 引语佐证（受访者编号+市场+画像）→ 证据类型 → 业务含义（"这意味着______应该______"）。
4. **四类证据标签**：每个发现必须标注——验证型（定性发现+定量证实，最高置信）/ 修正型（定性显著但定量显示量级小）/ 解释型（定量现象+定性解释机制）/ 单源型（仅一边支撑，置信降级，转下轮假设）。
5. **So What 强制**：每个数据发现后必须跟一句业务动作句。写不出"So What"的数据进附录，不进正文。
6. **反例检验**：成稿后单独过一遍，为每个核心结论找数据反例和未验证边界，写进"局限性"小节。
7. **摘要最后写**：摘要每条结论注明对应章节号，保证翻到该章能看到数据出处。

## 工作流程

### 第一步：需求承接（3 分钟）
确认三件事，说不清就先问，不急着开工：
- 这份报告要支持什么**决策**？（不是"了解用户"，而是"决定宣发预算往哪投"）
- 交付物给谁看？（老板/产品/市场，决定详略与语言）
- 已有什么数据？（定性/定量/缺什么，决定哪些结论注定只能降置信）

### 第二步：画逻辑树
```
业务问题：______
├── RQ1：______（对应第__章）
│     └── 预期结论方向：______
├── RQ2：______（对应第__章）
└── ...
每章只回答分配给它的 RQ，章与章之间要有推进关系（前章结论是后章前提）。
```

### 第三步：建证据账本（模板）
| 结论编号 | 结论摘要 | 定量出处 | 定性出处 | 证据类型 |
|---------|---------|---------|---------|---------|
| 3-1 | | 问卷Q__交叉表 | 访谈P__ | 验证/修正/解释/单源 |

### 第四步：写正文
- 章内顺序：数据结论 → 引语佐证 → 解读。不倒叙。
- 对比类分析一律用表格先行，段落只做解读。
- 占位符体系（写初稿时）：`【待填：xxx】`标记数据位，`【建议区】`标记待用户拍板的口径决策。初稿成稿后逐个消灭。

### 第五步：自审清单（成稿后逐项打勾）
- [ ] 每个核心结论可追溯到具体数据/受访者？
- [ ] 每章结论回答了分配的 RQ？
- [ ] 单源发现全部标注置信降级？
- [ ] 局限性小节诚实写了边界（样本偏差、版本错位、宣称vs行为）？
- [ ] 摘要每条挂了章节号？
- [ ] 无出处但"听起来很对"的句子全部清除？

### 第六步：多模型交叉评审（Agent Loop）
初稿完成后，用另一个模型（或新会话）执行审查提示词：
```
你是研究报告审查员。逐条检查以下报告：
1. 每个结论与其声称的证据是否真的支撑（结论-证据对应关系）
2. 数字前后是否一致（摘要vs正文vs图表）
3. 逻辑链是否有跳跃（前句推出后句是否需要未声明的假设）
4. 是否存在选择性呈现（对不支持结论的数据沉默）
只输出问题清单，按严重度排序，不写客套话。
```

## AI 协作分工

**AI 擅长**：访谈逐字稿主题聚类与引语提取、开放题语义分类、格式化排版、语言润色、逻辑树穷举展开、按模板生成图表、按本骨架做交叉评审。

**人必须做**：交叉分析选题（哪两个变量交叉有意义是业务判断）、统计显著 vs 业务显著的裁决、最终置信度评级、建议优先级取舍。

**给 AI 写报告的提示词顺序**（顺序错了就是逻辑混乱的主要来源）：
① 给逻辑树 → ② 给证据账本 → ③ 指令"只使用账本内证据，写不出出处的句子删除" → ④ 要求每条结论标注证据编号 → ⑤ 才让它写正文。

## 常见翻车点

| 症状 | 病因 | 解法 |
|------|------|------|
| 摘要说A正文说B | 摘要先写了 | 摘要最后写+挂章节号 |
| 结论"很有道理"但没数据 | 跳过证据账本 | 硬规则2 |
| 每章都像独立文章 | 没画逻辑树 | 硬规则1，章间推进关系 |
| 被一两个精彩故事带偏 | 定性压倒定量 | 修正型证据标签 |
| 报告读不出"所以呢" | 缺 So What | 硬规则5 |
| 下一轮研究从零开始 | 假设清单缺失 | 结论遗留缺口转"待验证假设清单"（H编号格式：假设+来源+验证方法） |
