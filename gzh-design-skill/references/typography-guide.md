# 公众号排版最佳实践指南

本文档提供针对微信公众号文章的排版最佳实践，确保内容在移动端有良好的阅读体验。

## 一、整体结构

### 文章长度
- **短文**：800-1500 字，适合快讯、通知、小贴士
- **中文**：1500-3000 字，适合常规推文、教程
- **长文**：3000-5000 字，适合深度文章、系列教程
- **超长文**：5000 字以上，建议拆分为系列文章

### 段落控制
- 每段建议 3-5 行（移动端约 4-6 行）
- 段落间空行，增加呼吸感
- 避免大段纯文字，每 300-500 字插入图片或视觉元素

### 标题层级
```
H1 - 文章标题（仅一个）
├── H2 - 主要章节
│   ├── H3 - 子章节
│   │   └── H4 - 小节（如需要）
│   └── H3 - 子章节
└── H2 - 主要章节
```

**注意**：不要跳级使用标题（如 H2 直接跳到 H4）

## 二、字体与排版

### 字号建议
| 元素 | 建议字号 | 说明 |
|------|---------|------|
| H1 标题 | 22-24px | 醒目但不夸张 |
| H2 标题 | 18-20px | 清晰区分章节 |
| H3 标题 | 16-18px | 区分小节 |
| 正文 | 15-16px | 移动端最佳阅读字号 |
| 引用 | 14-15px | 略小于正文 |
| 代码 | 13-14px | 等宽字体 |
| 注释 | 13-14px | 辅助说明 |

### 行高与间距
- **行高**：1.6-1.8 倍（正文），1.4-1.5 倍（标题）
- **段间距**：15-20px
- **字间距**：0.5-1px（中文适当增加字间距提升可读性）

### 对齐方式
- **正文**：两端对齐（justify）或左对齐
- **标题**：居中或左对齐，根据风格选择
- **引用**：左对齐
- **图片**：居中

## 三、颜色使用

### 文字颜色
- **正文**：#3f3f3f 或 #333333（深灰，比纯黑柔和）
- **次要文字**：#888888 或 #999999
- **标题**：使用主题色或 #333333
- **链接**：使用主题色，可加下划线

### 背景颜色
- **主背景**：#ffffff（白色）
- **引用块**：#f7f7f7 或主题色浅色变体
- **代码块**：#282c34（深色）或 #f5f5f5（浅色）

### 颜色对比度
确保文字与背景的对比度满足 WCAG AA 标准：
- 正常文字：对比度 ≥ 4.5:1
- 大号文字（18px+）：对比度 ≥ 3:1

## 四、内容元素

### 图片
- **宽度**：不超过 1080px，高度自适应
- **格式**：照片用 JPEG，图表用 PNG，动图用 GIF
- **大小**：单张不超过 2MB（公众号限制）
- **位置**：建议居中，图片下方可加说明
- **间距**：图片上下各留 15-20px 间距

```markdown
![图片描述](图片链接)
*图片说明文字*
```

### 代码块
- 指定语言以启用语法高亮
- 代码块前添加简要说明
- 超过 20 行考虑分段展示
- 使用行内代码标注文件名、变量名等

```markdown
以下示例展示如何使用该函数：

\`\`\`python
def hello(name):
    print(f"Hello, {name}!")

hello("World")
\`\`\`
```

### 引用块
- 用于强调重要内容
- 引用他人观点或文字
- 提示性信息（注意、警告等）

```markdown
> **重要提示**：请确保在操作前备份重要数据。
```

### 列表
- 并列要点用无序列表
- 有顺序的步骤用有序列表
- 每项不宜过长，建议 1-2 行

```markdown
**功能特点：**
- 简洁易用，零学习成本
- 支持多种主题样式
- 实时预览排版效果
```

### 表格
- 避免过宽的表格（移动端显示不佳）
- 列数建议不超过 4 列
- 复杂数据考虑转换为列表或图表

```markdown
| 参数 | 类型 | 说明 |
|------|------|------|
| name | string | 用户名 |
| age | int | 年龄 |
```

## 五、移动端适配

### 屏幕尺寸考虑
- 主流手机宽度：375px（iPhone）、360px（Android）
- 内容区域宽度：约 320-340px（扣除边距）
- 图片需自适应宽度

### 排版优化
- **避免**：过宽的表格、大段代码、复杂的多列布局
- **推荐**：短段落、列表化、图文混排
- **字号**：不小于 14px，确保可读性

### 触摸友好
- 链接间距适当，避免误触
- 按钮类元素尺寸不小于 44x44px
- 图片可点击放大查看

## 六、SEO 与阅读体验

### 开头优化
- 前 100 字内出现核心关键词
- 开头简明扼要，吸引读者继续阅读
- 可使用引导性问题或场景描述

### 结构清晰
- 使用目录（长文必备）
- 章节间有过渡语
- 重要内容加粗或使用引用块强调

### 结尾设计
- 总结全文要点
- 引导互动（提问、投票等）
- 相关推荐链接

## 七、常见排版问题

### 问题 1：图片显示不全
**原因**：图片过宽
**解决**：设置 `max-width: 100%`，或裁剪图片

### 问题 2：代码溢出
**原因**：代码行过长
**解决**：
- 设置 `overflow-x: auto` 或 `white-space: pre-wrap`
- 手动换行长代码
- 使用 `word-break: break-all`

### 问题 3：表格错位
**原因**：移动端宽度不足
**解决**：
- 减少列数
- 使用响应式表格设计
- 转换为列表展示

### 问题 4：字体不统一
**原因**：使用了不通用字体
**解决**：使用系统字体
```css
font-family: -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
```

### 问题 5：颜色对比度低
**原因**：浅色文字配浅色背景
**解决**：使用对比度检查工具验证，确保 ≥ 4.5:1

## 八、排版检查清单

发布前检查以下项目：

- [ ] 标题层级正确，无跳级
- [ ] 段落长度适中（3-5 行）
- [ ] 图片大小合适，加载正常
- [ ] 代码块有语法高亮
- [ ] 表格在移动端显示正常
- [ ] 链接可点击，颜色醒目
- [ ] 字号不小于 14px
- [ ] 颜色对比度达标
- [ ] 无错别字、语法错误
- [ ] 开头吸引人，结尾有互动
